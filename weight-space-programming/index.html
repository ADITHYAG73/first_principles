I gave Opus 5.5 the prompt and nothing else

A blind attempt at “Sparks of Weight-Space Programming”, and how it compares with GPT-6 Astra.

Adithya Giridharan, with Claude as tutor and editor · 8 Nov 2026 · all code, logs and edits ↗

Last week Rikiya Takehi, Jayden Teoh, Alex Zhang and Omar Khattab at MIT CSAIL published Sparks of Weight-Space Programming. Their claim is that a frontier language model can read and write the weights of another neural network directly. Nobody trains anything. The model looks at the numbers and decides what to change.

The model they used is GPT-6 Astra, OpenAI’s flagship, released in September. Given the raw weights of a small game-playing network, Astra names the game it was trained on. It writes game-playing networks from scratch that outplay networks trained for 100 million steps. And in the experiment that got me, it takes Qwen3.5-0.8B, a small open reasoning model, and makes it better at math by hand-editing 0.016% of its weights: MATH-500 goes from 7.9% to 48.1%, and the same edit makes it better at following instructions too.

I was fascinated, and a little annoyed with myself, because in hindsight it sounds so simple. These models already read text, images, audio and video. A list of floating-point numbers is one more thing to read. I wanted to see it for myself, so I gave the same task to a different frontier model, Claude Opus 5.5, and told it nothing else.

What exactly did Opus get?

I opened an empty folder and gave Opus the task prompt the authors gave Astra, word for word. No link to the post, no logs, no checkpoint. The rules in that prompt are strict:

  • Edit, don’t train. Weight values can be changed directly. No gradients, no optimizers, no fitting.
  • Ten forward passes, total. One pass either lets the model answer up to 512 problems, or has it read up to 1,024 texts while recording what happens inside. Everything else is a Python session and the weights.
  • No shortcuts. The embeddings and final norm are off limits, and making the model stop thinking early doesn’t count as a fix.

Astra worked inside a harness the authors built. Opus had only the prompt, so it built its own: it rented one AWS g5.xlarge (a single NVIDIA A10G GPU) and wrote the code to run and grade the model. Then it worked through its ten passes over about a day, much of it while I slept.

How does the model fail?

The first pass was diagnosis: the untouched model answering 256 practice problems, twice each. The model is not bad at math. It is bad at stopping. The authors found the same thing, and they point out that Qwen’s own model card warns this model is prone to thinking loops.

The last line then repeats × 767 until the token limit. The model never closed its thinking, so it never gave an answer and scored zero, though it had worked out 198 (220 × 0.9) in its first few lines.1

That is the common case: in 81 of 115 grade-school loops, the correct answer had already appeared earlier in the thinking. Not every loop starts from a right answer, though. On a problem about Zach saving for a $100 bike, the model counted only his babysitting money ($65 + $14 = $79, instead of $65 + $5 + $10 + $14 = $94), got $21 instead of $6, then wrote “Wait, if he earns $14, he needs $0.” 1,602 times.

And the loop feeds itself. When the model re-read its own loops, every lap made the next lap more certain. The chance of writing anything other than the repeat shrinks toward zero:2

Which part of the network keeps the loop going?

Qwen3.5-0.8B has 24 layers. Six of them use full attention, each with eight attention heads: small units that look back over the text and carry information forward. A loop like Zach’s is easy to sustain if some head does one simple thing: find the previous copy of the current phrase, and copy the word that came after it.

Several heads look back like this. Opus ranked them by something else: how hard each one pushes the model toward writing the repeated word, inside loops and in normal reasoning. Three stood out.

The three heads Opus switched off

How strongly each head pushes the model toward the word it writes next, inside loops and in normal reasoning. Each pushes about seven times harder inside a loop.2

What does “switching a head off” mean in the weights?

Each attention layer ends in an output matrix with 2,048 columns. Head \(h\) owns columns \(256h\) to \(256h+255\): its 256 numbers pass through those columns and come out as 1,024 numbers added to the token’s running state. Set a head’s columns to zero and that head writes nothing. Every other weight is unchanged.

With those three heads off, accuracy on fresh practice problems roughly quadrupled, from about 12% to about 45%.1 Here is one problem, before and after, with the same random seed in both runs:

The problem states that the number of ants doubles every hour. This is an example of exponential growth. We can represent this using the formula:
$$N(t) = N_0 \times (2)^t$$
Where:
*   $N(t)$ is the number of ants at time $t$.
*   $N_0$ is the initial number of ants (at time $t=0$).
*   $t$ is the time in hours.
*   $2$ is the growth factor (since it doubles every hour).

**2. Identify the Given Values**
*   **Initial amount ($N_0$):** 50 ants.
*   **Time ($t$):** 5 hours.

Substitute the known values into our formula:
$$N(5) = 50 \times 2^5$$

Opus also checked for the obvious cheat. Did the edit just make the model stop thinking early? No. Its correct answers thought for longer than the original's did. They were not cut short; they were let out of the loop.

Why not switch off more heads?

Some loops survived, and Opus traced them to two more heads, in layer 23. Switching those off completely cut the loops further but broke something else. Twenty-three answers ended like this:

How does this compare with Astra?

After the run I showed Opus the original post, the authors’ public logs and their released checkpoint. The authors ran Astra three times, with 10, 25 and 50 forward passes. They agree with Opus more than I expected:

  • Same diagnosis. In Astra’s 50-pass run, 85 of its first 96 answers hit the limit.
  • Same suspects. Both measured which heads look back at the previous lap, and found the same top three: layer 15 head 7, layer 11 head 1 and layer 23 head 5.
  • Same head. Astra’s 25-pass run ended by switching off exactly layer 15 head 7.
  • Same warning. That run also tried removing layer 23 head 5 and dropped it, because it hurt normal arithmetic more than the loops. It is one of the two heads whose full removal broke Opus’s boxed answers.
  • Same layers. Astra traced the looping to layers 15 and 19.

Where they split is the part of the network they cut. Astra’s best run, with 50 passes, left the heads alone. It found one direction in the 1,024-number state that marks “I’m repeating myself”, then reversed it inside the 64 MLP neurons per layer that write it most. For each chosen neuron’s output column \(w\):

\[ w \;\leftarrow\; w \;-\; 6\,u\,\big(u^{\top} w\big) \]

Here \(u\) is the unit-length repetition direction, so \(u^{\top}u = 1\). Look at what happens to the part of \(w\) that lies along \(u\):

\[ u^{\top} w \;\longrightarrow\; u^{\top} w - 6\,(u^{\top}u)\,(u^{\top} w) \;=\; -5\,\big(u^{\top} w\big) \]

That part is reversed and amplified five times, not deleted. Everything in \(w\) at right angles to \(u\) is untouched. Opus’s edit changes 1.3 million weights; Astra’s changes about 130,000.

Astra also checked that the direction is what matters: the same size of edit along a random direction did nothing (+1.6 points, within noise). And its edit reaches well beyond the problems it was tuned on. On the full benchmarks it lifts grade-school math, competition math, and instruction following, which it was never aimed at:

On the same 64 held-out problems, using the authors’ released per-problem results:6

Astra with 50 passes is better, mostly on grade-school problems. Opus with 10 passes is far ahead of Astra with 10 or 25. That gap needs an asterisk.

Did Opus play fair?

Not entirely. The prompt says only the forward-pass tool may run the network. The tool returned the 1,024-number state between layers, but not what each head did inside a layer. So Opus re-implemented the attention layers in plain PyTorch,4 fed them the recorded inputs and read each head’s output separately. That is how it measured each head’s push, and the push is what found the heads that worked.

That is running part of the network outside the tool. The authors state the rule plainly in the same post: “running the network or any of its layers on any input” is not allowed.

Astra followed it. In its 10-pass run it could only see where heads look, so it switched off the two that look hardest at the previous lap, layer 15 head 7 and layer 11 head 1, and gained 0.8 points, which is noise. So the 10-pass comparison is not a fair race. The edit itself is a legitimate weight edit, and every number saying it works comes from real runs of the model. But the microscope that found it was not allowed. Opus flagged this itself in its own write-up, before it had seen the post.

Can you trust a result a model produced?

A model ran this experiment and a model wrote it up, so the fair worry is that nobody checked the work. I had the two models check each other, and I checked the original claim myself.

Astra went through Opus’s run and found a real mistake. Opus had said the individual held-out answers were gone. In fact its own backup had quietly copied all 512 of them to cloud storage. Astra recovered them, regraded every one, and got exactly the numbers Opus had reported.5 Without being told, it also flagged the rule Opus broke.

Opus, in turn, compared the checkpoint the authors released with the original model, weight by weight. Only the two matrices their records describe had changed. And when I ran that checkpoint on a GPU of my own, the first 64 MATH-500 problems went from 9.4% to 58.2%. The headline result in their post is not an artefact of their setup.

What we still don’t know

This is one run on a small test. The held-out set is 64 problems, so any single number here could move by several points on different problems. Opus ran once, and so did each of Astra’s configurations, so I don’t know how much a second attempt would differ.

Opus’s edit is probably not the best it could have been. It tried only two strengths for its heads, and it never checked that switching off three random heads does nothing, a control Astra did run for its own edit. Its explanation for why the layer-23 heads break the boxed answers is a guess it never tested.

And the authors found that Astra’s edit also improved instruction following, not just math. Nobody has checked whether Opus’s edit does the same.

What I make of it

Two different frontier models, given the same prompt, found the same failure, went to the same layers and singled out the same head. They differ in where they cut. Opus removed the heads that copy the loop forward. Astra reversed the internal state that says “we’re in a loop”.

Those may be two halves of the same machine. Astra’s direction shows up strongly in Opus’s own recordings of loops, rising even before a loop starts, and Opus’s edit shrinks it by only 10–14%.6 If that is right, the two edits might stack. I haven’t tested it yet.

The authors’ own follow-up sharpens this. On Gemma 3 270M, a small model that rarely loops, Astra could not raise math scores at all. In their words, editing weights “could remove an obstacle that hid an ability, but it could not add an ability the model lacked.” Both edits here work because Qwen already knew the math.

What stays with me is how small the edits are. Zero a few columns, or reverse one direction in 128 neurons, and a model that almost never finishes starts finishing, and mostly getting it right. The editing is the easy part. Seeing where to edit is the whole job, and these models are starting to do the seeing.
