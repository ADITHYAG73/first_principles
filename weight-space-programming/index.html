I gave Opus 5.5 the prompt and nothing else

A blind attempt at “Sparks of Weight-Space Programming”, and how it compares with GPT-6 Astra.

Adithya Giridharan, with Claude as tutor and editor · 8 Nov 2026 · all code, logs and edits ↗

Last week Rikiya Takehi, Jayden Teoh, Alex Zhang and Omar Khattab at MIT CSAIL published Sparks of Weight-Space Programming. Their claim is that a frontier language model can read and write the weights of another neural network directly. Nobody trains anything. The model looks at the numbers and decides what to change.

The model they used is GPT-6 Astra, OpenAI’s flagship, released in September. Given the raw weights of a small game-playing network, Astra names the game it was trained on. It writes game-playing networks from scratch that outplay networks trained for 100 million steps. And in the experiment that got me, it takes Qwen3.5-0.8B, a small open reasoning model, and makes it better at math by hand-editing 0.016% of its weights. MATH-500 goes from 7.9% to 48.1%.

I was fascinated, and a little annoyed with myself, because in hindsight it sounds so simple. These models already read text, images, audio and video. A list of floating-point numbers is one more thing to read. I wanted to see it for myself, so I gave the same task to a different frontier model, Claude Opus 5.5, and told it nothing else.

What exactly did Opus get?

I opened an empty folder and gave Opus the task prompt the authors gave Astra, word for word. No link to the post, no logs, no checkpoint. The rules in that prompt are strict:

  • Edit, don’t train. Weight values can be changed directly. No gradients, no optimizers, no fitting.
  • Ten forward passes, total. One pass either lets the model answer up to 512 problems, or has it read up to 1,024 texts while recording what happens inside. Everything else is a Python session and the weights.
  • No shortcuts. The embeddings and final norm are off limits, and making the model stop thinking early doesn’t count as a fix.

Astra worked inside a harness the authors built. Opus had only the prompt, so it built its own. It rented one AWS g5.xlarge (a single NVIDIA A10G with 24 GB of memory), wrote the code that runs and grades the model, a counter for the ten passes, and watchdogs that shut the machine down when idle. It worked for about a day, much of it while I slept, and terminated the machine at the end (journal).

How does the model fail?

The first pass was diagnosis: the untouched model answering 256 practice problems, twice each. The model is not bad at math. It is bad at stopping.

The model often had the answer before it looped: in 81 of 115 grade-school loops, the correct answer had already appeared earlier in the thinking. And the loop feeds itself. When the model re-read its own loops, its confidence in the next token rose with every lap, from about 84% on the first repeat to over 99% by the seventh (notes, F1–F3).

Which part of the network keeps the loop going?

Qwen3.5-0.8B has 24 layers. Six of them use full attention, each with eight attention heads: small units that look back over the text and carry information forward. A loop like Zach’s is easy to sustain if some head does one simple thing: find the previous copy of the current phrase, and copy the word that came after it.

Several heads look back like this. Opus ranked them by something else: how hard each one pushes the model toward writing the repeated word, inside loops and in normal reasoning. Three stood out.

Push = the head’s direct contribution to the score of the token actually written next, averaged over tokens, in logit units. From 16 loops and 12 clean solutions (cell 15, output).

What does “switching a head off” mean in the weights?

Each attention layer ends in an output matrix with 2,048 columns. Head h owns columns 256h to 256h+255: its 256 numbers pass through those columns and come out as 1,024 numbers added to the token’s running state. Set a head’s columns to zero and that head writes nothing. Every other weight is unchanged.

With the first three heads off, Opus tested on problems it had never used. Accuracy went from 12.9% to 44.9% on one fresh set and from 10.9% to 45.7% on another, with the same random seeds for both models (write-up, §3). Here is one problem from the first set, before and after:

Opus also checked for the obvious cheat. Did the edit just make the model stop thinking? No. Correct answers from the edited model thought longer: a median of about 10,000 tokens before closing, against about 4,000 for the original. They were not cut short. They were let out of the loop.

Why not switch off more heads?

Some loops survived, and Opus traced them to two more heads, in layer 23. Switching those off completely (run E2) cut loops further but broke something else. Twenty-three answers ended like this:

GSM8K train #1512 · second edit (E2), layer-23 heads fully off

The result is consistent.

Opus’s guess was that those heads also carry the prompt’s instruction to box the answer forward. It did not test that guess directly. It turned the two heads down to half strength instead (run E3), and on 256 problems never used for any decision, E3 beat the three-head edit by 7.4 points (standard error 2.1). It had written down that decision rule before seeing those results (journal, 00:45 IST, 5 Nov).

The last test used 64 problems from the benchmarks themselves: 32 from MATH-500 and 32 from GSM8K’s test set, four attempts each. They were chosen and graded on the remote machine, so Opus never saw them.

How does this compare with Astra?

After the run I showed Opus the original post, the authors’ public logs and their released checkpoint. The authors ran Astra three times, with 10, 25 and 50 forward passes. They agree with Opus more than I expected:

  • Same diagnosis. In Astra’s 50-pass run, 85 of its first 96 answers hit the limit.
  • Same suspects. Both measured which heads look back at the previous lap, and found the same top three: layer 15 head 7, layer 11 head 1 and layer 23 head 5.
  • Same head. Astra’s 25-pass run ended by switching off exactly layer 15 head 7.
  • Same warning. That run also tried removing layer 23 head 5 and dropped it, because it hurt normal arithmetic more than the loops. It is one of the two heads whose full removal broke Opus’s boxed answers.
  • Same layers. Astra’s best edit sits in layers 15 and 19.

Where they split is the part of the network they cut. Astra’s best run, with 50 passes, left the heads alone. It found one direction in the 1,024-number state that marks “I’m repeating myself”, then reversed it inside the 64 MLP neurons per layer that write it most. For each chosen neuron’s output column w:

w ← w − 6 · u (uᵀ w)

The part of w along the direction u becomes −5 times what it was: reversed and amplified, not deleted. Opus’s edit changes 1.3 million weights; Astra’s changes about 130,000.

On the same 64 held-out problems, scored from the authors’ released per-problem results (same_problems.json):

Astra with 50 passes is better, mostly on grade-school problems. Opus with 10 passes is far ahead of Astra with 10 or 25. That gap needs an asterisk.

Did Opus play fair?

Not entirely. The prompt says only the forward-pass tool may run the network. The tool returned the 1,024-number state between layers, but not what each head did inside a layer. So Opus re-implemented the attention layers in plain PyTorch (recon.py), fed them the recorded inputs and read each head’s output separately. That is how it measured each head’s push, and the push is what found the heads that worked.

That is running part of the network outside the tool. The authors state the rule plainly in the same post: “running the network or any of its layers on any input” is not allowed.

Astra followed it. In its 10-pass run it could only see where heads look, so it switched off the two that look hardest at the previous lap, layer 15 head 7 and layer 11 head 1, and gained 0.8 points (standard error 3.4). So the 10-pass comparison is not a fair race. The edit itself is a legitimate weight edit, and every number saying it works comes from real runs of the model. But the microscope that found it was not allowed. Opus flagged this itself in its write-up, before it had seen the post. Astra flagged it independently when I asked it to audit the run.

Who checked whom?

I didn’t want to take either model’s word for anything, so I had each check the other.

  • Astra audited Opus (evidence audit, mechanism audit). It found one thing Opus got wrong: Opus had written that the per-answer held-out results were deleted, but its own 20-second backup had already copied them to cloud storage. Astra recovered all 512 answers and regraded them. Every number Opus reported matched.
  • Opus audited Astra’s release (comparison). The released checkpoint differs from the original model in exactly two matrices, 64 columns each, 130,188 values, matching the authors’ logs.
  • I re-ran the authors’ checkpoint on my own rented GPU: the first 64 MATH-500 problems went from 9.4% to 58.2%. Their headline claim holds up.

What this does not show

The held-out test is 64 problems, not the full benchmarks, so each number carries several points of noise. Opus ran once, and so did each Astra configuration; a second run of either could land differently. Opus tried only two strengths for its heads, so its edit is probably not the best one possible, and unlike Astra it ran no random-edit control. The reason the layer-23 heads break the boxed answers is a guess. And Opus never measured anything beyond math, while the authors report Astra’s edit also lifting instruction following.

What I make of it

Two different frontier models, given the same prompt, found the same failure, went to the same layers and singled out the same head. They differ in where they cut. Opus removed the heads that copy the loop forward. Astra reversed the internal state that says “we’re in a loop”.

Those may be two halves of the same machine. Astra’s direction shows up strongly in Opus’s own recordings of loops, rising even before a loop starts, and Opus’s edit shrinks it by only 10–14% (comparison). If that is right, the two edits might stack. I haven’t tested it yet.

What stays with me is how small the edits are. Zero a few columns, or reverse one direction in 128 neurons, and a model that almost never finishes starts finishing, and mostly getting it right. The editing is the easy part. Seeing where to edit is the whole job, and these models are starting to do the seeing.
